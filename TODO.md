## Test coverage audit

### Missing test coverage

- [ ] `server::lockout_secs` — no direct test of the exponential backoff formula. Boundary values worth covering: count < `MAX_AUTH_FAILURES` (0), count == threshold (30s), count == 2×threshold (60s), saturation at `MAX_LOCKOUT_SECS`.
- [ ] `server::per_ip_limit_middleware` — no test that exceeding `MAX_CONNECTIONS_PER_IP` (10) returns 429.
- [ ] `server::request_timeout_middleware` — no test that a slow request times out at `REQUEST_TIMEOUT_SECS`.
- [ ] Auth-failure map eviction (`AUTH_MAP_MAX = 10_000` cap, expired-entry pruning, oldest-evict fallback in `auth_middleware` lines 252–263) — entirely untested. This is the IPv6 spoofing defense.
- [ ] Password length validation in `server::run` — `MIN_PASSWORD_LEN = 12` is never exercised by a test (config with `"pw":"short"` should be rejected).
- [ ] `MAX_UPLOAD_SIZE` (512 MB) enforcement — no test that the streaming counter rejects with 413 when exceeded.
- [ ] `client::validate_pkg_spec` — no direct test (only exercised transitively through `validate_manifest_path`). Missing cases: empty string, leading `.`, trailing `.`, each `FORBIDDEN_SPEC_CHARS` byte, non-printable bytes.
- [ ] `upload::search` — has no direct test (only the helper paths in `search_pin_version_is_canonicalized` exercise `fetch_manifest`).
- [ ] `upload::resolve_mappings`, `upload::glob_base_dir`, `upload::create_package_zip` — only indirectly tested via `upload()` integration. Worth direct unit tests, especially `glob_base_dir` (no glob, leading glob, glob in middle).
- [ ] `main::parse_package_spec` — no test. Used at every CLI entry; trivial logic but covers canonicalization roundtrip.
- [ ] `shim::is_gui_exe` — no test. Build a synthetic PE header and verify CLI vs GUI subsystem detection.
- [ ] `shim::pathdiff` — no test. Worth: same-dir, deeper child, sibling-down, completely separate trees, different drives → `None`.
- [ ] `platform::restrict_to_owner_if_inherited` — no test on either platform. The Unix branch (4 lines) is testable in CI.
- [ ] `platform::write_or_rename` (Windows branch) — the "rename and retry" path is untested. Could be tested by locking the destination open with `FILE_SHARE_READ` only and asserting a `.0.__blob__` file appears.
- [ ] `platform::cleanup_with_retry` — no test of the exponential-backoff retry behavior.
- [ ] `tls::generate_keys`, `ensure_certs`, `current_fingerprint` — no direct tests. Roundtrip (`generate → current_fingerprint`) is one assertion.
- [ ] `client::HttpClient::download_to_file` and `post_with_progress` — no test of the failure paths (non-200 response, broken stream).

### Missing edge cases

- [ ] `server::validate_uploaded_manifest` — tested for self-dep, unsafe link path, and link-target-not-in-files. Missing: `manifest.name != expected_name` (URL says `foo` but body says `bar`), dependency name with `FORBIDDEN_SPEC_CHARS`, JSON depth at exactly 32 vs 33.
- [ ] `server::is_safe_segment` — no test for trailing whitespace (`"foo "`) or trailing dot (`"foo."`). Worth pinning the URL behavior.
- [ ] `client::validate_manifest_path` — known gap from prior security review still present, no test: trailing dot per segment (`"foo./bar"`), trailing space per segment (`"foo /bar"`), control chars (`\x1b`, `\r`, `\n`, `\t`) anywhere in `file` or `dest_dir`. These let an attacker craft a manifest whose path conflict detection sees as distinct but Windows resolves to the same file.
- [ ] `repo::ParsedVersion::parse` — missing: empty input, dot-only input (`".."`, `"..."`), numeric segments larger than `u64::MAX` (parses to 0 silently — is that the intent?), `"1-"` (empty pre-release tag).
- [ ] `upload::upload` — no test that uploading a manifest whose `links` value isn't in `files` fails on the client side (tested server-side; the client-side guard at upload.rs:282 should be pinned too).
- [ ] `install::extract_zip` — no test for the per-file `MAX_EXTRACT_SIZE` or aggregate `MAX_TOTAL_EXTRACT_SIZE` rejection. A 1-entry zip whose `entry.size()` declares > 1 GB, or two entries whose decompressed sum exceeds 2 GB.
- [ ] `install::download_zip` cache invalidation — `cache_reuse_skips_download` tests the reuse path, but not the "manifest changed → re-download" path (cached manifest differs from freshly fetched).
- [ ] `server::get_file` — confinement gap from prior security review: uses `canonical.starts_with(canonical_version_dir)` rather than `starts_with(canonical_packages)`. A symlink at `packages/foo/` pointing outside the repo would slip through. Worth a test that creates such a symlink and asserts 400.
- [ ] Network failure handling: `client::HttpClient::send` maps `reqwest::Error` to `ConnectionRefused`, but there's no test that timeouts or connection resets surface as a useful error string to the user.

### Test structure issues

- [ ] `test_config` is duplicated almost verbatim in 4 files (`install.rs`, `upload.rs`, `remove.rs`, `shim.rs`) and a fifth, slightly different variant lives in `server.rs`. Move to `testutil::server_helpers::test_config(port, base, fingerprint)`.
- [ ] `create_test_repo` (toolA + toolB) is duplicated in `install.rs` and `remove.rs` byte-for-byte. Move to `testutil::helpers`.
- [ ] `create_diamond_repo` is duplicated in `install.rs` and `remove.rs` with minor differences (`install.rs` adds a `toolE` package). Factor the loop body into a shared `create_pkg_with_deps(base, name, ver, deps, file)` helper.

### Findings still present (carried from v1.8.4 review)

#### Medium

- [ ] `client::validate_manifest_path` accepts trailing dots/spaces per segment and accepts control characters (ESC, CR, LF, TAB). On Windows, file APIs strip trailing dots/spaces, so two paths that look distinct to the conflict check can resolve to the same on-disk file — one package can silently overwrite another's file. Same strings see no terminal-escape sanitization when printed by `blob info`/`list`/`search --long`/`install`. Fix: `trim_end_matches` per segment for `.` and ` `; reject bytes < 0x20.
- [ ] `server::get_file` confinement check is narrower than `delete_version` (uses canonical version dir rather than canonical packages root). A symlink at `packages/<name>/` pointing outside the repo would be followed. Align with `delete_version`.

#### Low

- [ ] `constant_time_eq` early-returns on length mismatch — leaks username/password length via timing.
- [ ] `find_map` over user list short-circuits on match — leaks the index of the matched user via timing. Fold both checks into a single non-short-circuiting accumulator.
- [ ] Client `fetch_manifest`/`fetch_index` (`resp.json()`) and `download_to_file` have no body size limit — a hostile/compromised server can OOM the client or fill its disk.
- [ ] Server config (`server.json`) password is plaintext and not auto-ACL-restricted the way client `config.json` is.
- [ ] Cache integrity: cached zips are only validated against a cached manifest equality check, not against a content hash signed by the server. A local attacker with write to `~/.blob/cache/` can swap binaries.

## Refactoring audit

### High-value, low-risk (recommend)

- [ ] **Test helper duplication: `test_config`.** 4× verbatim copies in `install.rs:781`, `upload.rs:411`, `remove.rs:136`, `shim.rs:151`, plus a fifth slight variant in `server.rs`. All build the same `Config`.
  **Fix**: add `pub fn test_config(port: u16, base: &Path, fp: &str) -> Config` to `testutil::server_helpers`; delete the four duplicates.
  **Tradeoff**: zero — these are byte-identical and any future tweak needs to be made once instead of four times.

- [ ] **Test helper duplication: `create_test_repo` (toolA+toolB).** Verbatim copies in `install.rs:760` and `remove.rs:116`.
  **Fix**: move to `testutil::helpers::create_toolab_repo(base)`.
  **Tradeoff**: none.

- [ ] **Post-error cleanup pattern in `post_upload`.** The triple `let _ = tokio::fs::remove_file(&tmp_path).await; cleanup_empty_package_dirs(&dir, &canonical_packages).await; return Err(...)` appears 5× (server.rs:731-733, 740-742, 746-748, 753-755, 763-765).
  **Fix**: extract `async fn cleanup_and_fail(state, ip, method, path, status, msg, tmp, dir, root) -> Result<…>` returning the appropriate `StatusCode`. Cuts ~15 lines and removes the risk of forgetting one of the cleanup steps in a future error branch.
  **Tradeoff**: argument list is wide; consider grouping `(tmp, dir, root)` into a small `UploadDirs` struct.

### Medium-value (optional)

- [ ] **"Compare old vs new resolved manifest paths, delete moved files" block.** Lines 506–521 of `install.rs` (in `install`) and 686–701 (in `update`) are identical 15-line blocks: build `new_paths` via `resolve_manifest_paths`, walk `old_pkg.files`, delete each `old_path` that's not still produced in the same location.
  **Fix**: extract `fn cleanup_moved_files(name, new_manifest, db, config) -> io::Result<()>`.
  **Tradeoff**: borderline — Rule of Three says wait. Recommend extracting now only because both copies are nontrivial (15 lines, branches) and any future change must be applied to both.

- [ ] **`state.index.read()` lock+error pattern.** Appears 3× in server.rs (`get_index`:423, `get_versions`:445, `get_file`:497). Each is: `let Ok(index) = state.index.read() else { log_entry(...) ; return Err(500); }`.
  **Fix**: a thin helper `fn read_index_or_500(&self, ip, method, path) -> Result<RwLockReadGuard<RepoIndex>, StatusCode>` cuts boilerplate.
  **Tradeoff**: helpers that wrap `Result<…, StatusCode>` are slightly awkward to call. Low value because the duplication is short.

### Not worth the cost (leave as-is)

- **`is_safe_segment` (server.rs) vs `validate_pkg_spec` (client.rs).** Look similar but `is_safe_segment` is for URL path components (looser char set, allows `.json`) and `validate_pkg_spec` for package-name strings. The current split is load-bearing.
- **`grouped_help_template` in main.rs.** Long but linear; one concern. Don't split.
- **Auth-failure map eviction logic.** Complex (51 lines around server.rs:248–275) but each step encodes a specific DoS defense. Splitting would scatter the policy. Add a unit test instead.
- **Exhaustive match arms in `ParsedVersion::cmp` (repo.rs:118–124).** Required by the type system.
